# Aura Ledger


Aura Ledger is an offline-first portfolio crash-protection prototype. It detects abnormal market stress, moves a simulated portfolio from equity into gold and cash, confirms recovery, then re-enters the same equity proxy. Every decision is recorded in a tamper-evident hash chain.

The demo is intentionally broker-agnostic: only `SimulatedBroker` needs replacing to connect a compliant live execution provider in the future. No external API calls occur while the app is running.

## Demo flow

1. **Detection Agent** calculates volatility, drawdown, momentum and equity/gold-divergence stress signals.
2. **Risk Agent** combines the transparent abnormal-market score with classifier probability to identify a defensive trigger.
3. **Execution Agent** sells the equity proxy, allocates 85% to gold and 15% to cash, then re-enters equity after an 8% recovery confirmation.
4. **Execution Controls** support **Auto Execution** (replay acts automatically) and **Manual Approval** (replay pauses before each sell or re-entry action).
5. **Ledger Agent** appends every decision to a SHA-256 hash chain that can be verified on screen.

## Quick start

Use Python 3.11 or later.

```bash
git clone <your-github-repository-url>
cd aura-ledger
python -m venv .venv
# Windows PowerShell
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python generate_demo_data.py
python train_model.py
streamlit run dashboard.py
```

The app opens at `http://localhost:8501`. Click **Start Replay** and choose a historical scenario. In **Manual Approval** mode, the replay stops before a portfolio transition and exposes **Approve & Continue**. In **Auto Execution** mode, validated historical decisions execute during the replay without a page refresh.

## Data

`data/prices.csv` must contain daily `date`, `equity_close`, and `gold_close` columns. The included `generate_demo_data.py` creates a deterministic, offline **synthetic** scenario spanning 2018, 2020, and 2022. It is suitable for a UI demo, but it is not real market data and must not be used to claim live strategy performance.

For a one-time replacement with market data, install `yfinance` separately and run:

```bash
pip install yfinance
python fetch_data.py
python train_model.py
```

The fetched data spans 2007-2023 and includes the 2008 Global Financial Crisis, 2018 Q4 selloff, 2020 COVID crash, and 2022 drawdown. `fetch_data.py` is never imported by or called from the dashboard. Once fetched, the dashboard remains fully offline.

## Validation commands

```bash
python -m src.data_loader
python -m src.detection
python -m src.classifier
python -m src.allocation
python -m src.portfolio
python -m src.ledger
python train_model.py
python -m src.backtest
```

The dashboard precomputes the backtest once and reveals it progressively, keeping replay smooth on a low-spec laptop. The training script reports precision, recall, and AUC on a chronological 75/25 holdout, then saves a full-history inference model for the local demo. This is a historical backtest and research prototype, not live validation or an investment-performance guarantee.

## Scope and honest limitations

- This is a simulated prototype, not investment advice or a live trading system.
- The included dataset is deterministic demonstration data; replace it with audited historical data before making performance claims.
- The hash chain makes local edits detectable but is not a deployed blockchain.
- A real deployment needs regulated execution, data governance, monitoring, risk limits, and jurisdiction-specific compliance (including SEBI requirements where applicable).
